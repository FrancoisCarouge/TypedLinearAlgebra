◆ is_same_scale()

template<typename Lhs , typename Rhs , typename LhsUnderlying , typename RhsUnderlying = LhsUnderlying>
auto fcarouge::typed_linear_algebra::internal::is_same_scale ( ) -> bool
constexpr

Whether the same stored number means the same value in two element types.

The storage holds bare numbers, each in its own element's unit. A computation on the storage is therefore only correct between elements of one scale, whether or not their types are the same: the speed and the velocity in meters per second share a scale, the meter and the kilometer do not. The typed values of the numbers zero and one are compared, the second telling scales apart, the first offsets. Types without a common type are not of one scale: comparing them directly may hard-error instead, as in Au and nholthaus/units between dimensions.

constexpr

Whether each element the storage of To cannot write keeps its value on conversion from From.

An element the storage cannot write, as a structural zero, is a constant of the storage, the value it reads by default. A conversion cannot change it, so it is only exact when converting the element keeps that value: a conversion between scales without an offset keeps a zero, one with an offset, as between temperatures in degrees Celsius and in kelvin, does not.

Read the storage element at the given typed matrix index(es).

Maps the index(es) to a storage row and column, see storage_position. Then reads through a composed typed_matrix storage, a two-index element access, or a materialized expression template, in that order. The row and column cast to the storage index type, so none reaches the storage through an implicit sign or narrowing conversion.

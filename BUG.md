# BUG

Findings in TypedLinearAlgebra, found while integrating it with [FrancoisCarouge/Kalman](https://github.com/FrancoisCarouge/Kalman) into [ArduPilot](https://github.com/FrancoisCarouge/ardupilot/tree/fcarouge). Copied from the TypedLinearAlgebra findings of the integration's [findings table](https://github.com/FrancoisCarouge/ardupilot/blob/fcarouge/docs/FCAROUGE_FINDINGS.md), which keeps the numbering and the Kalman-only findings.

Only blocking findings, and findings that prevent performance improvements or let regressions through, are kept; resolved findings are removed. Rechecked on 2026-10-18 against Kalman d80652ace, TypedLinearAlgebra a62bbca6e and mp-units c85584d65.

| ID | Library | Kind | Finding | Evidence | Suggestion | Status |
|---|---|---|---|---|---|---|
| F4 | Both | Embedded, CI | No CI coverage of a freestanding-like embedded configuration. Both libraries happen to build cleanly for Cortex-M4/M7 with `-fno-exceptions -fno-rtti -fsingle-precision-constant -Wdouble-promotion -Werror=shadow,undef,float-equal`, but nothing guards it. | Phase 0 probes with Arm GCC 15.2.; 2026-10-09: both projects added a real-time sanitizer CI job (host), still no `arm-none-eabi` cross build | Add a CI job cross-compiling the samples for `arm-none-eabi` with those flags and a code size report. | open |
| F13 | TLA | Build | TypedLinearAlgebra's mp-units support needs unreleased mp-units: `support/mp_units/fcarouge/mp_units.hpp` includes `mp-units/framework/vector_components.h`, which exists on mp-units `master` (2026-10-01) but not in the latest release v2.5.0, and `support/mp_units/CMakeLists.txt` fetches mp-units without `GIT_TAG`. | mp-units v2.5.0 and `master` trees.; 2026-10-16: TypedLinearAlgebra 44f245794 drops its own tuple protocol for vector quantities and relies on the one of mp-units `master`, still fetched without `GIT_TAG`; 2026-10-20: mp-units c85584d65 (master) broke the WebAssembly build, Emscripten 6.0.8's Clang rejecting its reworked representation character constraints for `milli<kelvin>`; ArduPilot pins ef8653eab again | Pin the mp-units commit (or require a released version once available) and document it. | open |
| F14 | TLA | Docs, embedded | Using the mp-units support in an embedded, `-fno-exceptions`, `-Werror=undef` build needs undocumented setup: mp-units must be included as system headers (its headers test undefined macros such as `MP_UNITS_COMP_MSVC`), and `MP_UNITS_HOSTED=0` is required because the hosted `inplace_vector::emplace_back` throws. With that setup the `[m, m/s]` example costs 18 bytes on Cortex-M4. | Phase 3 probe (`mp_probe.cpp`) on GCC 14/15, clang 20/21, Arm GCC 15.2.; 2026-10-11: with GCC 16 (Arch Linux CI) mp-units turns its throwing constraints on by itself (`__cpp_constexpr_exceptions`), which include a hosted-only header and stop the freestanding build ("This header is not available in freestanding mode"); `MP_UNITS_API_THROWING_CONSTRAINTS=0` is needed too. This one is an mp-units defect, worth reporting there; 2026-10-14: in the same configuration `abs()` of a quantity does not compile (no `abs` for the representation without the hosted `<cmath>`), and a scan-build build with `-fno-builtin` makes gcc reject the constant evaluation of the C library `pow`, `sqrt` and `cbrt` that mp-units calls unqualified (`reference.h`, `math.h`) | Document an embedded configuration for the mp-units support (system includes, `MP_UNITS_HOSTED=0`, `MP_UNITS_API_CONTRACTS=0`, `MP_UNITS_API_THROWING_CONSTRAINTS=0`) and cover it in the CI job proposed in F4, with the newest GCC. | open |
| F17 | Both | Packaging | The mp-units `element_caster` specializations are defined twice, in Kalman's `support/mp_units/fcarouge/mp_units.hpp` and in TypedLinearAlgebra's file of the same path and name: including both redefines them, and putting both directories on an include path makes one shadow the other. | Both files.; 2026-10-18: after Kalman d80652ace the two files share their path and name; ArduPilot includes Kalman's integration headers by a path below `support/` to avoid the shadowing | Keep one owner (TypedLinearAlgebra) and have Kalman use it. | open |
| F22 | Both | Build | Compile cost per translation unit (g++ 15, `-O2`): `kalman.hpp` 2.2 s / 154 MB, `typed_linear_algebra.hpp` 2.1 s / 185 MB (about 1.3 s of each is `<format>`/`<print>`, included even when nothing is formatted), with TypedLinearAlgebra's mp-units support 5.8 s / 383 MB. Including them from a widely included header would add minutes to an ArduPilot build; ArduPilot confines them to one source file. | Header-only compile timing.; re-measured 2026-10-09 with `-fsyntax-only` (not comparable with the figures above): `kalman.hpp` 1.6 s / 150 MB, `typed_linear_algebra.hpp` 2.0 s / 180 MB, mp-units support 6.0 s / 370 MB; 2026-10-13, scaling: a translation unit with a typed 24x24 covariance of 576 element types and one scalar fusion compiles in 3.2 s / 590 MB (g++ 15 `-O2`, 1.6 s / 400 MB for the headers), a Kalman filter of 24 states in 10 s / 1.4 GB; 2026-10-14: mp-units quantity and SI unit headers alone cost 0.6 s / 210 MB per translation unit, `AP_LinearAlgebra_Units.h` (with TypedLinearAlgebra) 1.7 s / 390 MB, which keeps units off ArduPilot's widely included filter interfaces; 2026-10-16: the EKF3 velocity and position fusion source (typed 24-state covariance, SITL compile command) takes 9.0 s and 880 MB, unchanged within 2% from mp-units ef8653eab to c85584d65 despite the latter's compile-time work | Split formatting out into opt-in headers, offer forward declarations for the filter type, and keep heavy machinery out of the main include path. | open |
| F25 | TLA | Build | `typed_matrix::data()` returns `std::forward_like<decltype(self)>(self.storage)`. With clang (20, 21) and Ubuntu 24.04's default libstdc++ 14.2, whose `std::forward_like` has a deduced `decltype(auto)` return type, this fails: "function 'forward_like<...>' with deduced return type cannot be used before it is defined". libstdc++ 14.3 and 15 rewrote it with an explicit return type and work. | CI `test unit tests and sitl building (clang, ...)` on `test_linear_algebra`; libstdc++ `bits/move.h` 14.2 versus 14.3. | Avoid `std::forward_like` (an explicit cast on the deduced `self` category), or document libstdc++ >= 14.3 for clang. | open |
| F26 | TLA | Features | No typed block, segment or concatenation operations: a heterogeneous state vector such as EKF3's 24 states is used by groups (velocity, position, biases), and covariance updates work on blocks, but TypedLinearAlgebra only offers element access (`at<i>()`) and whole-matrix algorithms. Mapping EKF3's union of a state struct and a `Vector24` onto one typed vector would need per-element code. Nested typed matrices (`support/nested_typed_eigen`) may be the intended route; undocumented for this use. | TypedLinearAlgebra public API and README; EKF3 `state_elements`.; 2026-10-11: the EKFGSF innovation variance is the velocity block of the covariance plus R, the dense `H * P * transposed(H) + R` with a selector H, for want of a block, cost stack (F38), so ArduPilot reads the four elements as quantities; 2026-10-13: an EKF3 observation Jacobian has 2 to 6 non-zero elements of 24 (5 for the true airspeed), which the generated code exploits and a dense typed row cannot: `P * transposed(H)` and `H * P` do 24 terms per element instead of 5 | Typed `block<Row, Column, Rows, Columns>()` views or copies with their element types, and concatenation of typed vectors, or documented guidance for grouped states. A typed selection of rows or columns by a compile-time index list would serve both the grouped states and the sparse Jacobians. | open |
| F28 | TLA | Embedded | No compound assignment (`+=`, `-=`, `*=`) and no in-place algorithms: every typed operation returns a new matrix, and the wrappers copy whole backend matrices. `JTJ = JTJ + transposed(J) * J` on 9x9 floats needs a 1336 B stack frame on Cortex-M7 (ArduPilot limit 1300 B, `-Werror=frame-larger-than`), where the hand-written loop needs none beyond JTJ. ArduPilot works around it by type-checking the expression with an unevaluated `decltype` and accumulating on the backend storage. | `AP_AccelCal/AccelCalibrator.cpp` (CubeOrange, MatekF405 builds); again in `AP_Compass/CompassCalibrator.cpp`, where JTJ is also damped in place twice instead of copied, to fit the 2048 B calibration thread stack.; 2026-10-11: TypedLinearAlgebra 1b91a3678 adds an in-place `matrix_rank_1_update(x, y, a, a)`, exactly the accumulation needed, next to `add`, `matrix_product` and `scale`, but these exist only under `__cpp_lib_linalg` and delegate to `std::linalg` over `mdspan`: unavailable with libstdc++ 14 and 15, Arm GCC 15.2, and an owning backend such as ArduPilot's, so the workaround stays; 2026-10-13: for one scalar fusion on a 24-state typed covariance (EKF3), `P = P - K * transposed(PHt)` takes a stack frame of 9528 bytes in single precision and 19048 in double on Cortex-M7, against 608 and 1200 with the update done in place on the storage | Compound assignment operators delegating to the backend's in-place operations, and move/forwarding through `make_typed_matrix` so temporaries are not copied. Offer the in-place algorithms without `<linalg>`, through a backend dispatch as `transposed` has. | open, partly addressed |
| F29 | TLA | Embedded, build | `typed_linear_algebra.hpp` always includes the `std::chrono` integration (`chrono.tpp`, `<chrono>`) and `<format>`. ArduPilot defines `floor`, `exp`, `pow` and other double precision maths functions as function-like macros on boards without a double precision FPU; `<chrono>` parsed after them fails ("macro 'floor' passed 2 arguments"). ArduPilot saves and restores the macros around the includes. | MatekF405 copter build with the typed accelerometer calibrator; `AP_HAL/AP_HAL_Macros.h`. | Make the chrono and format integrations opt-in headers; keep the core header to `<tuple>`, `<concepts>`, `<utility>`. | open |
| F39 | TLA | Embedded | Constructing a large heterogeneous typed vector from its elements, `typed_row_vector<M, E0, ..., E23>{e0, ..., e23}`, emits a non-inlined `for_constexpr_detail<0, ..., 23>` function of about 1.2 kB on Cortex-M4 for each vector type (element casters applied one by one), and is slow: selecting the row and column of a 24-state covariance this way for six observation indexes added 21.9 kB of flash to a MatekF405 copter and made the fusion 7 times slower than the scalar code on the host. Copying the backend storage when the element types are the same costs nothing. | `AP_LinearAlgebra::row()`/`column()` first version, EKF3 `FuseVelPosNED`, `arm-none-eabi-nm -S` of the firmware (77 typed symbols, 44 kB). | When source and destination element types are identical, or the element casters are the identity, construct and convert by copying the storage; otherwise keep the per-element path. A block or selection API (F26) would avoid the construction altogether. | open |

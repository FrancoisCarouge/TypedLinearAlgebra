The code, data, and stack sizes in bytes of one operation on single precision floating point matrices of the freestanding backend, per configuration, operation, and optimization level, for version 0.4.0. A configuration is a matrix of the given rows and columns, multiplied by a matrix of the transposed shape. Each operation is measured twice: typed_ on the typed matrix, storage_ on its untyped freestanding storage. Each operation is linked alone, without any library, for a bare-metal Arm Cortex-M4 target with its single-precision floating-point unit, with GNU 14.2.1: -mcpu=cortex-m4 -mthumb -mfloat-abi=hard -mfpu=fpv4-sp-d16. The flash memory holds the .text, .rodata, and .data sections, the random-access memory the .data and .bss sections. The operands are the caller's; a matrix result is statically allocated, a scalar result returned. The stack is the worst case of the operation compiled as one function: a build that does not inline the library calls may use more or less. The configurations are in benchmark/footprint.

The typing costs zero bytes for the addition, the subtraction, the negation, and the scaling: their typed and storage sizes are verified equal. The typed product copies its result once more than its storage, except for a 1x1 matrix, multiplied as a scalar. The equality has no storage operation: the library implements it over the typed elements.
